A project Decision conflicting with a global Decision shadows it for this repository. Project Status/Debt names the pair — both ids, both authors — never silent, never auto-resolved. Status computation reads the global root read-only; absence of a global root is not an error.
- 2026-08-30 Maksim Yaromin: Design settled before code. (1) Discriminator: the project Decision's body cites the global Decision's id. Cross-scope supersession does not exist, so a Mention is the only edge a project record can draw at a global one — and the criteria's 'names the pair, both ids, both authors' rules out same-id shadowing, which would name one id. Same construction as the undeclared-pair signal, and its precision argument carries: a typed id in prose is a deliberate reference. Shared tags were rejected: a heuristic firing across scopes would nag every session. (2) Reading the second root: the Core takes it as a second Storage at construction, so Notebook::new and the 27 call sites that do not care keep their interface; Status is the one reader. A missing global root lists empty, so its absence needs no branch. (3) A mention that resolves in the user's notebook stops being a dangling mention: naming it missing would be a false claim now that it resolves. (4) Write-time is out of scope: decide's nudge still calls such a citation dangling, because making create global-aware would thread the second root through every write for a hint. Filing that as a finding.
- 2026-08-30 Maksim Yaromin: Shipped and green. The signal is DebtSignal::Shadow{project,user}, rendered 'shadow: <project> (<author>) over global <user> (<author>)' by both surfaces through code()/line(). Two rules keep it honest without a path comparison: only an id the user's notebook alone carries is a shadow — a citation this notebook resolves is about this notebook's record and belongs to undeclared-pair — so a notebook read beside itself finds nothing, and no root equality has to be guessed. And a citation the user's notebook holds stops being reported as dangling, because naming it missing is now false. The Core reads the second root through the same Storage seam: Notebook::beside_the_user, with Notebook::new and its 27 call sites untouched; records_in was extracted to read_records_in so both roots are read by one set of rules. Only the user's live Decisions are read — one listing and the files it names. Ran on the live notebook: the pair reached Status and the JSON debt rows, and no dangling-mention appeared beside it.
- 2026-08-30 Maksim Yaromin: The independent review found 13 items; seven were reproduced defects. (1) A broken user notebook — a file where the directory should be, or one that cannot be read — made every project status exit 1 with a message about the user's home. A second root is read for a hint on somebody else's dashboard, so it now leaves the hint out instead; unusable_root guards it too. (2) The guard skipped any target the project resolves, and resolves counts archived ids: a rule this project retired silently hid the user's, which still stands. The guard now asks for a live record of this notebook's own. (3) Dangling-mention was suppressed only for the user's live Decisions, so citing its Note or its retired rule still claimed the id names nothing. The whole second notebook is read now, through the same Resolver as the first, and the claim is true again. (4) An invalid record of the user's notebook was named as half a pair, under an id its own envelope disowns; is_standing now excludes it as undeclared-pair already did. (5) 'over global' asserted an override the trigger never establishes — a citation can be agreement. The line is now '<-> global', parallel with undeclared-pair, and the precedence rule lives in the variant's doc. (6) The doc claimed the order the records name them while the rank re-sorted; the rank now keeps that order. (7) The tests transcribed too little: the end-to-end assertion passed with the sides swapped, the retired case asserted only the absence of one code, and JSON had no coverage at all. All assert line() exactly now. Also: Notebook lost the user field and the beside_the_user constructor — a field one method read, on the handle that also runs expunge — for a status parameter; records_in was a pure delegate and is gone; process and concurrency tests now pin HOME, which status reads on every run. Kept as shipped: shadow stays a Debt signal, which the criteria sanction.
