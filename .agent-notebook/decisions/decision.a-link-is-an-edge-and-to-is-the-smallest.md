A link whose target is a record id relates the two records under the link's kind, and the tool walks it back: show lists linked-by, graph draws the edge under the link's own word, list --for and graph --for reach what links a record, and --focus walks the same edge. A to field names whom a Task or a Question is addressed to; the record waits on that person while it waits at all, a Question open or a Task in review, and a narrowed Status shows what waits on the reader beside what they hold and wrote. That is the whole hand-off. The notebook is working memory an agent reads, not a channel people write to each other through: review lives in the tracker, and the Tasks behind a change are found from git, since the notebook is committed beside the code. So the skill mentions a link and to in one sentence each and teaches no workflow around them, and what the issues asked beyond that was left out on purpose: no --to-me, no Debt row naming an addressee, no --match over link lines, and start does not erase to, so a Task submitted again waits on the same person.
