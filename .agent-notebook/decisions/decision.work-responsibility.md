Creating a Task records its author without assigning work unless an assignment was requested explicitly. Starting records responsibility; the current recipient also sees work waiting on their response. A person can own several active Tasks while each identified session remembers its own focus. A whole-result Task represents accountability for the outcome, not inherited ownership of every child. Before taking that result, inspect its composition and agree how to coordinate any unfinished part already assigned to a colleague. A request for one part does not claim its siblings. Dependencies declare required completion, not membership: a coordinating Task can start before its prerequisites finish, but successful closing requires them to be closed. Cancellation remains explicit and does not cancel related work. These rules preserve a shared planning pool and independent execution without adding assignment cascades or session fields to records.
